# 配置变更回滚告警处理方案

## 告警名称
- **告警名**: `ConfigChangeRollbackNeeded`
- **告警级别**: 严重
- **触发条件**: 配置变更后 5 分钟内错误率上升超过 20%

## 问题描述
配置变更可能导致系统不稳定，需要快速回滚。

## 排查步骤

### 步骤1: 查看变更记录
- 查询配置变更系统或 Git 提交记录
- 确认变更内容和时间

### 步骤2: 分析错误日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `application-logs`
- **时间范围**: 变更后 10 分钟
- **查询条件**: `ERROR OR FATAL`

### 步骤3: 对比变更前后指标
- CPU、内存、错误率、响应时间

## 常见原因分析

### 原因1: 配置参数错误
**特征**:
- 新增配置项缺失
- 格式不正确

**处理方案**:
1. 立即回滚配置
2. 验证配置语法
3. 分批次灰度发布

### 原因2: 依赖资源变化
**特征**:
- 数据库连接串变更
- 外部服务地址变更

**处理方案**:
1. 验证新资源可达性
2. 回滚到旧配置
3. 逐步切换

### 原因3: 并发或连接池配置不当
**特征**:
- 线程数或连接数变更导致资源耗尽

**处理方案**:
1. 回滚到稳定值
2. 评估合理值后重新变更

## 紧急处理措施
- 立即执行配置回滚
- 重启受影响的实例
- 通知相关团队

## 验证步骤
1. 确认错误率恢复正常
2. 验证业务功能
3. 分析变更失败原因

## 预防措施
- 实施灰度发布
- 配置变更需审批
- 保留配置历史版本
