# 负载均衡健康检查失败告警处理方案

## 告警名称
- **告警名**: `LBHealthCheckFailed`
- **告警级别**: 严重
- **触发条件**: 负载均衡健康检查失败率超过 50% 持续 2 分钟

## 问题描述
健康检查失败会导致负载均衡摘除所有后端，服务完全不可用。

## 排查步骤

### 步骤1: 查看负载均衡后端状态
- 登录控制台查看后端服务器健康状态
- 确认哪些实例被标记为不健康

### 步骤2: 检查健康检查配置
- 检查健康检查路径、端口、超时时间
- 确认健康检查 URL 是否返回 200

### 步骤3: 测试后端实例健康检查端点
```bash
curl -I http://<backend_ip>:<port>/health
常见原因分析
原因1: 健康检查路径不存在
特征:

返回 404

处理方案:

修正健康检查路径

创建健康检查端点

或临时改用 TCP 检查

原因2: 后端实例负载过高
特征:

健康检查响应超时

处理方案:

增加后端实例

优化后端性能

调整健康检查超时时间

原因3: 网络隔离
特征:

负载均衡无法访问后端端口

处理方案:

检查安全组规则

检查 VPC 网络配置

验证路由表

紧急处理措施
手动将健康实例重新加入服务

临时将不健康实例设为健康

扩容后端实例

验证步骤
确认健康检查通过率 > 90%

验证服务可用性

检查流量分配是否均匀
