# API 网关超时告警处理方案

## 告警名称
- **告警名**: `APIGatewayTimeout`
- **告警级别**: 警告
- **触发条件**: 网关超时率超过 5% 持续 3 分钟

## 问题描述
API 网关超时会导致用户请求失败，影响前端体验。

## 排查步骤

### 步骤1: 查看网关日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `gateway-access-logs`
- **查询条件**: `status:504 OR upstream_response_time:>3000`

### 步骤2: 检查上游服务健康
```bash
curl -I <upstream_url>
步骤3: 分析慢接口
从网关日志中提取耗时最长的接口

调用链追踪

常见原因分析
原因1: 上游服务响应慢
特征:

特定接口超时率升高

上游服务 CPU 或数据库负载高

处理方案:

优化上游接口性能

增加上游实例数

启用缓存

原因2: 网关配置不合理
特征:

proxy_read_timeout 过小

连接池不足

处理方案:

调整超时参数

增大连接池大小

启用 keepalive

原因3: 网络抖动
特征:

超时随机发生

丢包率高

处理方案:

检查网络链路

使用重试机制

部署多可用区

紧急处理措施
临时增大超时时间

降级非核心接口

重启网关实例

验证步骤
确认超时率降到正常水平（<1%）

测试核心接口响应时间

观察用户反馈
